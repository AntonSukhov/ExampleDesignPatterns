# Паттерн Сага (Saga)

## Описание

**Сага (Saga)** — архитектурный паттерн, который управляет сложной многошаговой бизнес-операцией, гарантируя согласованность данных через последовательное выполнение шагов и компенсацию при ошибках.

## Проблема

```
Client
    │
    ├── _headerRepo.CreateHeaderAsync(...)       ← ша 1: создан
    ├── _bodyRepo.CreateBodyAsync(...)           ← шаг 2: УПАЛО!
    └── ❌ Заголовок создан, тело не создано — данные рассинхронизированы
```

**Недостатки:**

- **Нет атомарности**: если шаг 2 падает, шаг 1 уже записан — данные частично сохранены
- **Нет компенсации**: созданный заголовок остаётся «висячим» — нет автоматического отката
- **Ручной откат**: клиент должен сам писать логику undo для каждого шага — дублирование и ошибки
- **Нет отслеживания состояния**: неизвестно, на каком шаге остановилась операция
- **Нарушение SRP**: клиент управляет последовательностью, откатом и состоянием

> ✅ Клиент должен вызвать один метод — а сага сама выполнит шаги и откатит при ошибке.  
> ❌ Проблема — когда клиент выполняет каждый шаг вручную и сам следит за откатом.

## Решение

Оркестратор, который управляет последовательностью шагов, отслеживает состояние и автоматически выполняет компенсацию:

```
Клиент                    Сага-оркестратор              Реализации
┌──────────────┐         ┌──────────────────┐        ┌─────────────────────┐
│ Client       │         │ DocumentCreation  │        │ DocumentHeaderRepo  │
│              │         │ Saga              │        │ DocumentBodyRepo    │
│ ExecuteAsync │───────→ │                   │        │ DocumentFooterRepo  │
│              │         │ Шаг 1: Header     │──────→ │ CreateHeaderAsync   │
│              │         │ Шаг 2: Body       │──────→ │ CreateBodyAsync     │
│              │         │ Шаг 3: Footer     │──────→ │ CreateFooterAsync   │
│              │         │                   │        │                     │
│              │         │ Ошибка → компенсация│──────→ │ Undo...Async        │
└──────────────┘         └──────────────────┘        └─────────────────────┘
```

**Сага** — оркестратор, который выполняет шаги последовательно и компенсирует в обратном порядке при ошибке.  
**Состояние саги** — отслеживает выполненные шаги через флаги (`IsHeaderCreated`, `IsBodyCreated`, `IsFooterCreated`).

> Клиент вызывает один метод `ExecuteAsync` — сага сама выполнит шаги и откатит при ошибке.  
> Компенсация выполняется в порядке «последний — первый»: `UndoFooter → UndoBody → UndoHeader`.

### Как работает

```
Выполнение (успех):
1. Шаг 1: CreateHeaderAsync() → IsHeaderCreated = true
2. Шаг 2: CreateBodyAsync()   → IsBodyCreated = true
3. Шаг 3: CreateFooterAsync() → IsFooterCreated = true
4. Возврат DocumentId

Выполнение (ошибка на шаге 2):
1. Шаг 1: CreateHeaderAsync() → IsHeaderCreated = true
2. Шаг 2: CreateBodyAsync() → ❌ ОШИБКА
3. Компенсация: UndoHeaderAsync() → откат шага 1
4. Проброс исключения клиенту
```

**Порядок выполнения:**

```
1. Сага создаёт состояние: DocumentSagaState { DocumentId, Status = Pending }
2. Последовательно выполняет шаги:
   - _headerRepo.CreateHeaderAsync(documentId, headerContent)
   - _bodyRepo.CreateBodyAsync(documentId, bodyContent)
   - _footerRepo.CreateFooterAsync(documentId, footerContent)
3. При ошибке — компенсирует в обратном порядке:
   - UndoFooterAsync() (если IsFooterCreated)
   - UndoBodyAsync() (если IsBodyCreated)
   - UndoHeaderAsync() (если IsHeaderCreated)
4. Обновляет статус: Status = Compensated
```

## Структура

| Компонент | Описание | Пример |
|-----------|----------|--------|
| **Saga (Orchestrator)** | Оркестратор, управляет последовательностью шагов и компенсацией | `DocumentCreationSaga` |
| **SagaState** | Модель состояния саги, отслеживает выполненные шаги | `DocumentSagaState` |
| **Step Repository** | Репозиторий для одного шага, содержит метод компенсации | `IDocumentHeaderRepository` |
| **SagaStatus** | Enum статусов жизненного цикла саги | `SagaStatus` |

## Преимущества

- **Автоматическая компенсация**: при ошибке все выполненные шаги откатываются в обратном порядке
- **Отслеживание состояния**: флаги `Is*Created` точно знают, какие шаги были выполнены
- **Простота клиента**: клиент вызывает один метод — не управляет последовательностью и откатом
- **Мониторинг**: статусы саги позволяют отслеживать прогресс и диагностировать проблемы
- **Разделение ответственности**: сага отвечает за оркестрацию, репозитории — за выполнение шагов

## Когда использовать

- Нужна многошаговая бизнес-операция, затрагивающая несколько хранилищ или сервисов
- Требуется гарантия согласованности данных через компенсацию, а не транзакции
- Шаги выполняются над разными агрегатами, которые не поддерживают распределённые транзакции
- Нужен мониторинг и логирование прогресса длительной операции

## Связь с другими паттернами

- **Unit of Work** — Unit of Work компенсирует в рамках одной БД одной транзакцией, Сага — через компенсацию across multiple services
- **Repository** — каждый шаг саги использует репозиторий для выполнения CRUD-операции
- **State Machine** — статусы саги (`Pending`, `HeaderCreated`, `Completed`, `Compensated`) — упрощённая машина состояний
