# Паттерн Репозиторий (Repository)

## Описание

**Репозиторий (Repository)** — архитектурный паттерн, который инкапсулирует логику доступа к данным, предоставляя коллекционно-ориентированный интерфейс для работы с сущностями.

## Проблема

```
Client
    │
    ├── new NpgsqlConnection(...)
    ├── new NpgsqlCommand("SELECT * FROM contracts")
    ├── new NpgsqlDataReader()
    ├── while(reader.Read())
    │   └── new ContractEntity { ... }
    │
    └── new NpgsqlCommand("DELETE FROM contracts WHERE id = @id")
```

**Недостатки:**

- **Прямая зависимость от БД**: клиент знает о PostgreSQL, SQL-запросах, `DbConnection`, `DbCommand`
- **Смешение логики**: клиент выполняет SQL, маппит данные и управляет жизненным циклом соединений
- **Нарушение SRP**: клиент отвечает за бизнес-логику, доступ к данным и маппинг
- **Сложность тестирования**: нельзя протестировать бизнес-логику без реальной базы данных
- **Дублирование SQL**: запросы разбросаны по коду — сложно менять структуру БД

> ✅ Клиент должен работать с коллекциями сущностей, а не с SQL-запросами.  
> ❌ Проблема — когда `SELECT * FROM contracts` и `NpgsqlConnection` разбросаны по клиенту.

## Решение

Слой абстракции между клиентом и хранилищем данных, предоставляющий коллекционно-ориентированный интерфейс:

```
Клиент                    Репозиторий                 Хранилище
┌──────────────┐         ┌──────────────────┐        ┌─────────────────────┐
│ Client       │         │ IContractRepo    │        │ ContractsDbContext  │
│              │         │                  │        │                     │
│ GetContracts │───────→ │ GetAllAsync()    │──────→ │ DbSet<Contract>     │
│ Remove()     │───────→ │ RemoveAsync()    │──────→ │ RemoveAsync()       │
└──────────────┘         └──────────────────┘        └─────────────────────┘
```

**Репозиторий** — предоставляет коллекционно-ориентированный интерфейс (`GetAll`, `Add`, `Remove`).  
**DbContext** — EF Core контекст, который инкапсулирует детали доступа к БД.

> Клиент работает только с `IContractRepository` — не знает о SQL, соединениях и маппинге.  
> Репозиторий скрывает детали хранилища за интерфейсом, работающим с сущностями.

### Как работает

```
Клиент запрашивает: repository.GetAllAsync()
    → Репозиторий обращается к DbContext
        → DbContext формирует SQL-запрос
            → БД возвращает данные
        → DbContext мапит данные в сущности
    → Репозиторий возвращает IReadOnlyCollection<ContractEntity>
```

**Порядок выполнения:**

```
1. Создаём DbContext
2. Создаём репозиторий, передавая ему DbContext
3. Вызываем методы репозитория:
   - var contracts = await repository.GetAllAsync()
   - await repository.RemoveAsync(10)
4. Клиент не знает о SQL — только о сущностях
```

## Структура

| Компонент | Описание | Пример |
|-----------|----------|--------|
| **IRepository** | Интерфейс репозитория, определяет CRUD-операции | `IContractRepository` |
| **Repository** | Реализация, использует DbContext для доступа к данным | `ContractRepository` |
| **DbContext** | Контекст ORM, инкапсулирует детали доступа к БД | `ContractsDbContext` |
| **Entity** | Сущность доменной модели | `ContractEntity` |

## Преимущества

- **Инкапсуляция доступа**: клиент не знает о БД, SQL и соединениях
- **Коллекционно-ориентированный интерфейс**: работаем с сущностями, а не с строками и колонками
- **Лёгкое тестирование**: можно замокать `IContractRepository` без реальной БД
- **Централизация изменений**: при смене БД меняется только репозиторий
- **Разделение ответственности**: клиент занимается бизнес-логикой, репозиторий — доступом к данным

## Когда использовать

- Нужно скрыть детали доступа к хранилищу от клиента
- Требуется возможность замены БД без изменения клиентского кода
- Нужно упростить тестирование через мокирование репозитория
- Клиент должен работать с коллекциями сущностей, а не с SQL

## Связь с другими паттернами

- **Unit of Work** — репозитории инкапсулируют CRUD, а UnitOfWork координирует их работу в транзакции
- **DbContext (ORM)** — EF Core контекст как конкретная реализация доступа к данным
- **Factory Method** — для создания сущностей при маппинге из БД
