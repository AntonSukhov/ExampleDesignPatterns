# Паттерн Диспетчер Изменений (Unit of Work)

## Описание

**Unit of Work** — архитектурный паттерн, который группирует операции с данными в одну транзакцию, обеспечивая атомарность, единую точку сохранения и отслеживание изменений.

## Проблема

```
Client
    │
    ├── workTypeRepository.CreateAsync(workType)
    │       └── await _dbContext.SaveChangesAsync()  ← сохранение 1
    │
    └── operationRepository.CreateAsync(operation)
            └── await _dbContext.SaveChangesAsync()  ← сохранение 2
```

**Недостатки:**

- **Нет атомарности**: если вторая операция упадёт, первая уже записана в БД — данные частично сохранены
- **Дублирование `SaveChanges`**: каждый репозиторий вызывает сохранение самостоятельно — клиент не контролирует границу транзакции
- **Рассинхронизация**: репозитории не знают друг о друге — нет единого представления о наборе изменений
- **Сложность отката**: при ошибке на втором шаге нужно вручную писать rollback-логику
- **Нарушение SRP**: репозиторий отвечает не только за CRUD, но и за жизненный цикл контекста и транзакции

> ✅ Репозиторий — это CRUD для одной сущности.  
> ❌ Проблема — когда `SaveChanges` вызывается внутри каждого репозитория и нет единой точки сохранения.

## Решение

Единый диспетчер, объединяющий репозитории и обеспечивающий сохранение всех изменений одной операцией:

```
Клиент                    Unit of Work                Реализации
┌──────────────┐         ┌──────────────────┐        ┌─────────────────────┐
│ Client       │         │ IUnitOfWork      │        │ ContractsDbContext  │
│              │         │                  │        │                     │
│ SaveData()   │───────→ │ WorkTypeRepo     │──────→ │ DbSet<WorkType>     │
│              │         │ OperationRepo    │──────→ │ DbSet<Operation>    │
│              │         │ SaveChangesAsync │──────→ │ SaveChangesAsync    │
└──────────────┘         └──────────────────┘        └─────────────────────┘
```

**UnitOfWork** — агрегирует репозитории, предоставляет единую точку `SaveChangesAsync`.  
**DbContext** — EF Core контекст, который отслеживает изменения и выполняет SQL за одним соединением.

> Репозитории не вызывают `SaveChanges` самостоятельно — они лишь добавляют изменения в `DbContext`.  
> Сохранение происходит через `unitOfWork.SaveChangesAsync()` — всё или ничего.

### Как работает

```
UnitOfWork.Create(workType)      → DbContext добавляет WorkType в отслеживание
UnitOfWork.Create(operation)     → DbContext добавляет Operation в отслеживание
UnitOfWork.SaveChangesAsync()    → DbContext отправляет INSERT для всех изменений одной транзакцией
```

**Порядок выполнения:**

```
1. Создаём UnitOfWork (DbContext + репозитории)
2. Вызываем репозитории для изменения данных:
   - workTypeRepository.CreateAsync(workType)
   - operationRepository.CreateAsync(operation)
3. Вызываем единственное сохранение:
   - unityOfWork.SaveChangesAsync()
4. Dispose — DbContext закрывает соединение
```

## Структура

| Компонент | Описание | Пример |
|-----------|----------|--------|
| **IUnitOfWork** | Интерфейс диспетчера, содержит репозитории и метод сохранения | `IUnitOfWork` |
| **UnitOfWork** | Реализация, агрегирует DbContext и репозитории | `UnitOfWork` |
| **DbContext** | Контекст ORM, отслеживает изменения сущностей | `ContractsDbContext` |
| **Repository** | CRUD-репозиторий для одного типа сущности | `WorkTypeRepository`, `OperationRepository` |

## Преимущества

- **Атомарность**: все изменения сохраняются одной транзакцией — всё или ничего
- **Единая точка контроля**: клиент управляет сохранением через один метод
- **Отслеживание изменений**: DbContext автоматически отслеживает добавленные, изменённые и удалённые сущности
- **Эффективность**: все SQL-запросы отправляются за одно соединение с базой данных
- **Простота отката**: при исключении в `SaveChangesAsync` все изменения откатываются автоматически

## Когда использовать

- Нужно гарантировать атомарность нескольких операций с данными
- Несколько репозиториев должны работать с одним DbContext
- Требуется единая точка сохранения для бизнес-операции
- Нужна возможность отката всех изменений при ошибке

## Связь с другими паттернами

- **Repository** — репозитории инкапсулируют CRUD, а UnitOfWork координирует их работу
- **Transaction Script** — UnitOfWork — часть скрипта транзакции, обеспечивающая атомарность
- **DbContext (ORM)** — EF Core контекст как конкретная реализация отслеживания изменений
