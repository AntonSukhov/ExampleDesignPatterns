# Паттерн Декоратор (Decorator)

## Описание

**Декоратор (Decorator)** — структурный паттерн проектирования, который добавляет объектам новые поведения без изменения их кода, оборачивая объект в специальную обёртку-декоратор.

## Проблема

```
ILogService
    ├── FileLogService     ← логирует в файл
    ├── DataBaseLogService ← логирует в БД
    └── EmailLogService    ← логирует по почте
```

**Недостатки:**

- **Жёсткая привязка**: если нужно логировать одновременно в файл и в БД — приходится создавать новый класс `FileAndDbLogService`
- **Взрыв классов**: для `N` способов логирования нужно `2^N` комбинаций — `FileLogService`, `DbLogService`, `FileDbLogService`, `FileDbEmailLogService`...
- **Нарушение OCP**: для добавления нового поведения нужно создавать новый класс, а не просто компоновать существующие
- **Невозможность компонуемости**: клиент не может динамически выбрать набор логирования в рантайме

> ✅ Нужно логировать в файл, БД и по почте — без создания `FileDbEmailLogService`.  
> ❌ Проблема — когда каждая комбинация требует нового класса.

## Решение

Оборачиваем объект в декоратор, который добавляет дополнительное поведение, вызывая исходный метод:

```
Клиент                    Декоратор                   Реализации
┌──────────────┐         ┌──────────────────┐        ┌─────────────────────┐
│ Client       │         │ LogServiceDecor  │        │ FileLogService      │
│              │         │                  │        │                     │
│ Log()        │───────→ │ _logService      │──────→ │ Log()               │
│              │         │                  │        │                     │
│              │         │ + Log()          │        │                     │
└──────────────┘         └────────┬─────────┘        └─────────────────────┘
                                  │
                                  ├── LogServiceDecor
                                  │     └── DataBaseLogService
                                  │
                                  └── EmailLogService
```

**Декоратор** — оборачивает `ILogService`, выполняет дополнительные действия и делегирует вызов внутреннему сервису.  
**Композиция**: декоратор может оборачивать другой декоратор — поведение складывается как матрёшка.

> Декоратор выполняет дополнительную логику (`Console.WriteLine`), затем делегирует вызов `_logService.Log(exception)`.  
> Новый способ логирования добавляется простой компоновкой — без изменения существующих классов.

### Как работает

```
Композиция:
LogServiceDecorator
    └── LogServiceDecorator (второй уровень)
            └── DataBaseLogService

Выполнение:
1. Второй декоратор: Console.WriteLine("Протоколируем... и выполняем дополнительные действия:")
2. Первый декоратор: Console.WriteLine("Протоколируем... и выполняем дополнительные действия:")
3. DataBaseLogService: Console.WriteLine("Сохраняем текст ошибки в таблицу базы данных.")
```

**Независимость от способа логирования:**

```
FileLogService                     DataBaseLogService                  EmailLogService
    │                                    │                                   │
    ▼                                    ▼                                   ▼
LogServiceDecorator ←────────── LogServiceDecorator ←────────── LogServiceDecorator
    │                                    │                                   │
    ▼                                    ▼                                   ▼
[только файл]                   [файл + БД]                        [файл + почта]
```

Количество комбинаций = `N + M` при количестве классов = `N + M`. Новый способ логирования не требует новых классов.

## Структура

| Компонент | Описание | Пример |
|-----------|----------|--------|
| **Component** | Базовый интерфейс для объектов, к которым можно добавить поведение | `ILogService` |
| **ConcreteComponent** | Базовая реализация компонента | `FileLogService`, `DataBaseLogService`, `EmailLogService` |
| **Decorator** | Базовый декоратор, содержит ссылку на компонент и делегирует вызов | `LogServiceDecorator` |
| **ConcreteDecorator** | Декоратор с конкретным дополнительным поведением | (в примере — `LogServiceDecorator` универсальный, но можно создать `EmailLogDecorator`, `DbLogDecorator`) |

## Преимущества

- **Открытость к расширению**: новое поведение добавляется компоновкой декораторов, а не созданием новых классов
- **Соблюдение OCP**: существующие классы не меняются — добавляется новая компоновка
- **Динамическая компонуемость**: набор логирования меняется в рантайме через `SetInnerLogService`
- **Принцип единственной ответственности**: каждый декоратор отвечает за одно дополнительное действие
- **Прозрачность**: клиент работает с `ILogService` — не знает, обернут объект или нет

## Когда использовать

- Нужно добавлять поведения объектам динамически и прозрачно для клиента
- Нужно отменять поведения путём удаления декоратора
- Нельзя расширить поведение подклассами (когда класс закрыт для наследования)
- Нужно избежать взрыва классов при множестве комбинаций поведения

## Связь с другими паттернами

- **Bridge** — оба разделяют ответственность на иерархии. Bridge разделяет *поведение* и *реализацию* на независимые иерархии, а Decorator динамически добавляет поведения
- **Facade** — Facade упрощает интерфейс сложной системы, а Decorator расширяет его
- **Composite** — оба строят иерархию объектов, но Composite работает с деревом, а Decorator — с одноуровневым обёртыванием
