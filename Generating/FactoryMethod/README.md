# Паттерн Фабричный метод (Factory Method)

## Описание

**Фабричный метод (Factory Method)** — порождающий паттерн проектирования, который определяет интерфейс для создания объектов, но позволяет подклассам решать, объекты какого класса создавать. Фабричный метод делегирует создание экземпляров своим подклассам.

## Проблема

```
Клиент                        Подключения к БД
┌──────────────────────┐     ┌──────────────────────────────────────┐
│ Client               │     │ SqlConnection                        │
│                      │     │ NpgsqlConnection                     │
│ Create(connection)   │───→ │                                      │
│                      │     │   1. Какой тип подключения создать?  │
│                      │     │   2. Какую строку подключения задать?│
│                      │     │   3. Как вернуть IDbConnection?      │
└──────────────────────┘     └──────────────────────────────────────┘
```

**Недостатки:**

- **Жёсткая привязка**: клиент напрямую создаёт конкретные объекты (`new SqlConnection(...)`, `new NpgsqlConnection(...)`), что связывает его с конкретными реализациями
- **Условные конструкции**: при поддержке нескольких типов подключения клиент содержит `if`/`switch` для выбора нужного класса, что разрастается при добавлении новых провайдеров
- **Смешение ответственности**: клиент отвечает не только за бизнес-логику, но и за создание объектов подключения
- **Нарушение принципа открытости/закрытости (OCP)**: добавление нового провайдера БД требует изменения клиентского кода

> ✅ Клиент должен вызвать один метод `Create()` — а не знать о `SqlConnection`, `NpgsqlConnection` и их конструкторах.  
> ❌ Проблема — когда клиент жёстко привязан к конкретному классу создаваемого объекта.

## Решение

Фабричный метод — интерфейс, который описывает общий контракт для создания объектов, а конкретные создатели решают, объект какого класса вернуть:

```
Клиент              Создатель (интерфейс)        Конкретные создатели
┌──────────────┐   ┌──────────────────────┐     ┌─────────────────────────┐
│ Client       │   │ IDbConnectionCreator │     │ SqlDbConnectionCreator  │
│              │   │                      │     │ NpgDbConnectionCreator  │
│ Create()     │──→│ Create(connectionString)│  │                         │
│              │   │                      │     │ Create()                │
└──────────────┘   └──────────────────────┘     └─────────────────────────┘
                                                    │           │
                                                    ▼           ▼
                                              ┌──────────┐ ┌──────────────────┐
                                              │ SqlConnection │ │ NpgsqlConnection │
                                              └──────────┘ └──────────────────┘
```

**Создатель** — интерфейс `IDbConnectionCreator`, объявляющий фабричный метод `Create()`.  
**Конкретные создатели** — `SqlDbConnectionCreator`, `NpgDbConnectionCreator`, реализующие фабричный метод и возвращающие конкретные объекты подключений.  
**Продукт** — `IDbConnection`, общий интерфейс для всех создаваемых подключений.

> Клиент работает с интерфейсом `IDbConnectionCreator` и вызывает `Create()` — конкретный создатель сам решает, объект какого класса вернуть, не раскрывая детали клиенту.

### Как работает

```
Клиент:
  IDbConnectionCreator creator = new SqlDbConnectionCreator();
  var connection = creator.Create("Data Source=.\\SQLEXPRESS;...");
  Console.WriteLine(connection.ConnectionString);

Конкретный создатель внутри:
  1. Получение строки подключения
  2. Создание конкретного объекта: new SqlConnection(connectionString)
  3. Возврат объекта как IDbConnection
```

**Упрощение создания объектов:**

```
Без фабричного метода (клиент создаёт напрямую):
  IDbConnection connection = new SqlConnection(connectionString);
  // при смене провайдера — другой класс:
  IDbConnection connection = new NpgsqlConnection(connectionString);

С фабричным методом (делегирование создателю):
  IDbConnection connection = creator.Create(connectionString);
  // смена провайдера = смена создателя, клиент не меняется
```

## Структура

| Компонент | Описание | Пример |
|-----------|----------|--------|
| **Creator** | Интерфейс, объявляющий фабричный метод | `IDbConnectionCreator` |
| **Concrete Creators** | Конкретные создатели, реализующие фабричный метод | `SqlDbConnectionCreator`, `NpgDbConnectionCreator` |
| **Product** | Общий интерфейс создаваемых объектов | `IDbConnection` |
| **Concrete Products** | Конкретные объекты, создаваемые фабричным методом | `SqlConnection`, `NpgsqlConnection` |
| **Client** | Использует создателя для получения объекта | `Client` |

## Преимущества

- **Снижение связанности**: клиент зависит от интерфейса создателя, а не от конкретных классов продуктов
- **Устранение условных конструкций**: логика выбора конкретного класса выносится из клиента в конкретные создатели
- **Расширяемость (OCP)**: новые типы продуктов добавляются как новые классы создателей, без изменения существующего кода
- **Единая точка создания**: вся логика создания объекта сосредоточена в одном месте — фабричном методе

## Когда использовать

- Заранее неизвестно, объекты каких классов потребуется создавать
- Нужно делегировать создание объектов подклассам
- Хочется избежать жёсткой привязки клиента к конкретным классам продуктов
- Нужно централизовать логику создания объектов

## Связь с другими паттернами

- **Abstract Factory** — Abstract Factory создаёт семейства связанных объектов, а Factory Method — один объект
- **Builder** — Builder пошагово создаёт сложный объект, а Factory Method возвращает готовый объект целиком
- **Prototype** — Prototype создаёт объекты путём клонирования, а Factory Method — через конструктор
