# Паттерн Шаблонный метод (Template Method)

## Описание

**Шаблонный метод (Template Method)** — поведенческий паттерн проектирования, который определяет скелет алгоритма в базовом классе, позволяя подклассам переопределять отдельные шаги алгоритма без изменения его структуры.

## Проблема

```
Клиент                        Калькуляторы стоимости
┌──────────────────────┐     ┌──────────────────────────────────────┐
│ Client               │     │ OrderCostCalculator                  │
│                      │     │ OtherCostCalculator                  │
│ Calculate(email,     │───→ │                                      │
│          products)   │     │   1. Валидация e-mail и товаров      │
│                      │     │   2. Расчёт стоимости товаров        │
│                      │     │   3. Расчёт скидки                   │
│                      │     │   4. Формула итоговой стоимости      │
└──────────────────────┘     └──────────────────────────────────────┘
```

**Недостатки:**

- **Дублирование скелета алгоритма**: при наличии нескольких калькуляторов каждая реализация повторяет одинаковую последовательность шагов (валидация → расчёт стоимости → расчёт скидки → вычисление итога)
- **Нестабильная структура алгоритма**: нет гарантии, что все калькуляторы выполняют шаги в одном порядке и не пропускают валидацию
- **Нарушение принципа DRY**: общий скелет алгоритма (валидация, формула итога) дублируется в каждой конкретной реализации

> ✅ Клиент должен вызвать один метод `Calculate()` — а не знать о шагах валидации, расчёта стоимости и скидки.  
> ❌ Проблема — когда каждый новый калькулятор дублирует одинаковую последовательность шагов алгоритма.

## Решение

Шаблонный метод — скелет алгоритма в абстрактном базовом классе, а конкретные шаги выносятся в абстрактные методы, которые подклассы переопределяют по необходимости:

```
Клиент              Базовый класс               Подклассы
┌──────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ Client       │   │ BaseOrderCostCalc.   │   │ OrderCostCalculator  │
│              │   │                      │   │                      │
│ Calculate()  │──→│ Сalculate()          │   │ - CalculateProductCosts()
│              │   │   └─ Validation      │   │ - PercentageDiscountCalculation()
│              │   │   └─ CalculateProd.  │   │                      │
│              │   │   └─ PercentageDisc. │   │                      │
│              │   │   └─ Итоговая формула│   │                      │
└──────────────┘   └──────────────────────┘   └──────────────────────┘
```

**Базовый класс** — `BaseOrderCostCalculator`, хранит общий скелет алгоритма и неизменяемые шаги (валидация, формула итога).  
**Шаблонный метод** — `Сalculate()`, определяет последовательность шагов алгоритма и не может быть переопределён.  
**Абстрактные шаги** — `CalculateProductCosts()`, `PercentageDiscountCalculation()`, которые подклассы реализуют по-своему.  
**Конкретный подкласс** — `OrderCostCalculator`, переопределяет шаги для своей логики расчёта.

> Клиент создаёт конкретный калькулятор и вызывает `Calculate()` — базовый класс управляет последовательностью шагов, а подкласс определяет детали каждого шага.

### Как работает

```
Клиент:
  var logger = new ConsoleLogger();
  var calculator = new OrderCostCalculator(logger);
  var total = calculator.Calculate(email, products);

Базовый класс внутри Сalculate():
  1. Валидация: e-mail и товары не пустые
  2. Вызов подкласса: CalculateProductCosts(products)
  3. Вызов подкласса: PercentageDiscountCalculation(email, products)
  4. Формула: total = productCosts - (productCosts / 100 * discount)

Подкласс OrderCostCalculator:
  - CalculateProductCosts:  Sum(p => p.Cost * p.Count)
  - PercentageDiscountCalculation: Random.Next(1, 30)
```

**Упрощение добавления нового калькулятора:**

```
Без шаблонного метода (дублирование скелета):
  class DiscountCalculator
  {
      public decimal Calculate(...)
      {
          // Валидация...
          // Расчёт стоимости...
          // Расчёт скидки...
          // Формула итога...
      }
  }

Со шаблонным методом (скелет в базовом классе):
  abstract class BaseOrderCostCalculator
  {
      public decimal Сalculate(...) { /* скелет один раз */ }
      protected abstract decimal CalculateProductCosts(...);
      protected abstract decimal PercentageDiscountCalculation(...);
  }

  class NewCalculator : BaseOrderCostCalculator
  {
      protected override decimal CalculateProductCosts(...) { /* своя логика */ }
      protected override decimal PercentageDiscountCalculation(...) { /* своя логика */ }
  }
```

## Структура

| Компонент | Описание | Пример |
|-----------|----------|--------|
| **BaseClass** | Определяет скелет алгоритма и абстрактные шаги | `BaseOrderCostCalculator` |
| **TemplateMethod** | Метод, определяющий последовательность шагов | `Сalculate()` |
| **AbstractSteps** | Абстрактные методы, переопределяемые подклассами | `CalculateProductCosts()`, `PercentageDiscountCalculation()` |
| **ConcreteClass** | Конкретная реализация шагов алгоритма | `OrderCostCalculator` |
| **Client** | Создаёт конкретный класс и вызывает шаблонный метод | `Client` |
| **ILogger** | Зависимость для логирования ошибок | `ConsoleLogger` |

## Преимущества

- **Устранение дублирования кода**: общий скелет алгоритма (валидация, формула итога) определяется один раз в базовом классе
- **Расширяемость**: новые калькуляторы добавляются как подклассы без изменения базовой логики
- **Контроль структуры**: последовательность шагов алгоритма жёстко задана в базовом классе и не может быть нарушена
- **Принцип DRY**: каждый шаг реализуется в одном конкретном подклассе

## Когда использовать

- Есть алгоритм со стабильной последовательностью шагов, но отдельные шаги различаются
- Нужно избежать дублирования одинакового скелета алгоритма в нескольких классах
- Требуется контролировать структуру алгоритма, позволяя подклассам расширять отдельные шаги
- Есть несколько похожих классов, отличающихся только реализацией некоторых шагов

## Связь с другими паттернами

- **Strategy** — Strategy заменяет весь алгоритм интерфейсом, а Template Method переопределяет отдельные шаги внутри фиксированного скелета
- **Factory Method** — Factory Method может создавать конкретные подклассы Template Method
- **Observer** — Observer определяет связи между объектами во время выполнения, а Template Method фиксирует структуру на этапе компиляции
